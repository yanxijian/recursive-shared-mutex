# Benchmark results: MinGW-GCC

- Toolchain: MinGW-GCC (g++.exe (x86_64-posix-seh-rev2, Built by MinGW-Builds project) 14.2.0)
- Generated by `benchmarks/run_bench.ps1`: medians of 1 run(s), 1s per run
- Commit: `5be31dd7279fa4bc54b94a9ffbb93911b7a8e676`
- Runner: GitHub Actions, job 39016637300 (shared hardware: expect drift between runs)
- Host hw_concurrency: 4
- Dataset: 1,048,576 x uint32 (~4 MiB); nested reenter depth 3; read window 24 / write window 12

> Absolute numbers are specific to the machine; the meaningful column is the speedup vs `recursive_mutex` measured in the same run.

> **Low-core host (4 cores).** Shared locking pays off when readers outnumber cores: below ~8 cores the
> readers barely overlap and RSM can look slower than `recursive_mutex`. These numbers are for run-to-run regression on this
> machine, not a statement about a many-core desktop.
